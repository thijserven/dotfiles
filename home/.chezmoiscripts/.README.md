# Lifecycle scripts

Thin lifecycle templates live under `common/`, `macos/`, and `linux/`. Shared VS Code/mise wrappers belong in `common/`; platform-specific package and Firefox wrappers live in each platform directory. Directory names organize scripts; template conditions still enforce platform gates. Plain shell implementations live in [`install/common/`, `install/macos/`, and `install/linux/`](../../install/README.md). Templates select platforms and `include` the shell scripts; implementation edits therefore change chezmoi's rendered script hash. Inputs read at runtime retain explicit hashes in wrappers. `DOTFILES_ROOT` supplies the working-tree path; standalone installers default to their repository location.

Documentation uses `.README.md` because chezmoi skips dot-prefixed files before script validation; ordinary `README.md` fails validation even when listed in `.chezmoiignore`. GitHub does not render `.README.md` automatically, so directory indexes link here explicitly.

chezmoi renders these scripts, runs `before` scripts before deploying files, then runs `after` scripts. Within each phase, relative script paths sort lexicographically: `common/` precedes `linux/`, then `macos/`. Numeric prefixes order scripts within each directory, not across directories or phases. Shared mise installation therefore still precedes macOS keybindings installation.

The [age-key pre-read hook](../../install/README.md) runs earlier than all scripts here. Keep key recovery there: encrypted source files must be readable before lifecycle scripts can run.

## State and reruns

`run_once_` scripts run once per content hash tracked by chezmoi. `run_onchange_` scripts run when rendered content differs from the last successful run. Neither means "every apply". Avoid editing the state database directly.

Prefer rerunning the specific needed command, such as `sh "$HOME/.local/share/chezmoi/install/macos/packages.sh"`, instead of resetting all script state. Review package installation and macOS defaults before rerunning them.

To intentionally reset all script history, chezmoi provides the following command. This resets more than one script: the next apply can rerun package installation, app setup, and system changes.

```sh
chezmoi state delete-bucket --bucket=scriptState
```

## Desktop startup on macOS

Borders and SketchyBar use Homebrew services. Their formulas provide login startup and `KeepAlive` crash recovery:

```sh
brew services list
brew services restart borders
brew services restart sketchybar
```

AeroSpace, [Hammerspoon](../private_dot_hammerspoon/README.md), and [Vicinae](../private_dot_config/vicinae/README.md) use repository-managed LaunchAgents. The desktop script enables and bootstraps missing agents after deployment; reapplying leaves loaded jobs alone. OrbStack opens once when the desktop script runs, without supervision or automatic restart after quit. AeroSpace and Hammerspoon native login startup are disabled in config. Keep Vicinae's **Launch at Login** setting off; its native login item is not managed by this repository.

Each agent runs `/usr/bin/open -W -a APP`: LaunchServices opens or attaches to the existing app, and `-W` waits for it to exit, even if already running. `KeepAlive = true` restarts after normal quits and crashes, not only failures. No direct app binary, `open -n`, polling loop, or process-name matching is used. launchd runs one waiter per label; LaunchServices avoids duplicate app launches, including overlapping native login requests. This does not prevent someone explicitly forcing another instance with `open -n`.

`ThrottleInterval = 1` limits rapid failure loops to roughly one launch per second. A normally running app relaunches as soon as launchd observes exit; macOS scheduling and app initialization mean zero downtime cannot be guaranteed. Agents only load in Aqua sessions and stop at logout/shutdown. Missing or broken apps retry rather than disabling supervision.

For maintenance, stop supervision first (replace `vicinae` with `aerospace` or `hammerspoon` as needed), then quit the app:

```sh
launchctl bootout "gui/$(id -u)/local.keepalive.vicinae"
# Resume supervision:
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.keepalive.vicinae.plist"
```

Plist changes take effect after bootout/bootstrap or next login. Test actual recovery after deployment by quitting each app and checking that one app instance returns; offline checks cannot validate GUI app behavior or permissions.

SbarLua needs Apple Command Line Tools. After a Lua major-version upgrade, follow [SketchyBar rebuild instructions](../private_dot_config/sketchybar/README.md). Some macOS defaults require logout/login.

## Number ranges

Use these ranges for new scripts, while preserving phase ordering:

| Range   | Responsibility            |
| ------- | ------------------------- |
| `00–09` | Prerequisites             |
| `10–19` | Package managers          |
| `20–29` | Packages                  |
| `30–39` | Extensions/tools          |
| `40–59` | Application configuration |
| `60–79` | Services/integrations     |
| `80–89` | OS configuration          |
| `90–99` | Finalization              |

Templates gate platform-specific actions; do not execute unrendered `.tmpl` files directly. Check shell syntax and inspect rendered wrappers without hooks or deployment; do not add or generate tests.
